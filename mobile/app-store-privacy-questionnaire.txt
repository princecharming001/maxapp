App Store Connect → App Privacy: use this as a checklist. Adjust if your production stack differs (e.g. you add analytics SDKs).

Data types you likely collect (verify against your privacy policy and backend):
- Contact info: email, phone (signup / account).
- User content: forum/channel messages, chat with Superpower (AI), profile bio, progress photos.
- Identifiers: account ID, auth tokens (device).
- Usage: course progress, schedules and task completions.

Sensitive:
- Photos: profile avatar, progress archive, channel and chat attachments. (The face scan was removed in the biohacking release — remove any face / biometric data answers and Photos-or-Videos entries that only existed for it.)
- Health & Fitness: onboarding goals (sleep, energy, focus, stress, training, skin and hair, longevity), routine level, wake/bed times and workout time — disclose as Health & Fitness if you treat these as fitness data.

Third-party SDKs (scan package.json / native projects before submitting):
- PostHog (posthog-react-native + @posthog/react-native-plugin), live once EXPO_PUBLIC_POSTHOG_KEY is set.
  Declare in App Privacy (all Linked to the user via account ID, NOT used for tracking, purpose Analytics + App Functionality):
    Usage Data: Product Interaction (screens, taps, session recordings with text inputs/images masked)
    Diagnostics: Crash Data, Performance Data, Other Diagnostic Data (errors)
    Identifiers: User ID

Linked to user: typically Yes for account-backed data.

Purposes: App functionality, customer support, compliance (moderation).

Tracking (ATT): only declare tracking if you or an SDK use data for cross-app advertising; otherwise answer accordingly.
